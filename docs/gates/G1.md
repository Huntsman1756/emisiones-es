# Gate G1 — PREREGISTRATION (instrument-defining securities terms)

Estado: **PREREGISTERED** — definido antes de seleccionar nuevos holdouts y
antes de cualquier desarrollo G1.

G0-D cerró con **FAIL** congelado en tag `g0-final-fail` (commit `fcd687f`).
La hipótesis amplia —valor contractual demostrable en todos los documentos del
lifecycle— quedó descartada con evaluación válida. G1 es una hipótesis nueva
y más estrecha, no una continuación ni un reintento de G0.

## 2. Scope — `INSTRUMENT_DEFINING` (congelado antes del holdout)

### 2.1 Taxonomía documental (AMEND-1)

Tres ejes independientes, nunca fusionados en un único "tipo":

```text
acquisition_surface   dónde se encontró el documento
                      (CNMV_CCFF | CNMV_ADMISSION | CNMV_REGISTRY | ...)

document_role         función semántica del documento
                      (FINAL_TERMS | SECURITIES_NOTE | BASE_PROSPECTUS |
                       SUPPLEMENT | CORRECTION | REGISTRATION_DOC |
                       ISSUE_DOC | ...)

scope_role            función en el producto
                      (INSTRUMENT_DEFINING | LIFECYCLE)
```

La superficie de adquisición no determina el rol: una fila del registro de
admisiones **no** es instrument-defining; una securities note encontrada a
través de esa fila sí lo es. Ejemplo G0 (X28), reclasificado:

```text
X28
  acquisition_surface = CNMV_ADMISSION
  document_role       = SECURITIES_NOTE
  scope_role          = INSTRUMENT_DEFINING
  instrument_class    = DEBT
```

Marco regulatorio: el Reglamento de Folletos (UE) 2017/1129 distingue el
*registration document* (información del emisor) de la *securities note*
(términos y condiciones y características del valor). Las final terms se leen
junto con el base prospectus y sus suplementos — rol propio, no se fusionan
con `SECURITIES_NOTE`.

### 2.2 Clasificación

```text
INSTRUMENT_DEFINING (gate contractual):
  FINAL_TERMS / CCFF de emisión          (plain_vanilla, coupon_variant,
                                          covered_bond, subordinated,
                                          structured)
  SECURITIES_NOTE del instrumento        (X28 y equivalentes)
  ISSUE_DOC específico                   (securitisation issue docs)
  prospectus que define el instrumento

LIFECYCLE (fuera del gate contractual):
  SUPPLEMENT, CORRECTION, REGISTRATION_DOC,
  documentos de admisión no-securities-note, COMMERCIAL_PAPER_PROGRAMME
```

`acquisition_surface`, `document_role` y `scope_role` de cada documento se
fijan en el manifest del nuevo holdout **antes** de ver su contenido. Ningún
documento cambia de clase después de evaluarlo.

## 3. Política de reutilización de datos G0

- Los 300+30 casos de los holdouts G0 quedan disponibles como **development**
  desde el tag `g0-final-fail`. Ya no son evidencia de generalización — el
  resultado FAIL quedó publicado y congelado.
- G1 requiere **holdouts completamente nuevos, nunca vistos**: nuevas emisiones
  adquiridas y congeladas antes de reglas/extractores G1.
- Ningún caso G0 puede entrar en el holdout G1.

## 4. Gates preregistrados

### 4.1 Safety (hard gates, inalterados)

```text
provenance evidence-backed          = 100%
unsupported / invented values       = 0
false-positive links                = 0
forced AMBIGUOUS                    = 0
```

### 4.2 Linkage

```text
decisiones: AUTO_LINKED | REVIEW_REQUIRED | NO_LINK

hard gates:
  FP links            = 0        (AUTO_LINKED incorrecto)
  forced links        = 0        (decidir sin evidencia suficiente)
  precision AUTO_LINKED ≥ 99%

métricas reportadas (sin threshold favorable post-hoc):
  cobertura automatizada = AUTO_LINKED correctos / EXACT_LINK gold
  abstenciones correctas (REVIEW_REQUIRED cuando gold lo requiere)
```

Una abstención correcta no se penaliza como falso enlace, pero la cobertura
automatizada se mide explícitamente — el recall 88.8% de G0 no puede esconderse
detrás de la precision.

Los defectos S7/S9 (RULE_DEFECT ×10) y la frontera S4 (demostrar vs inferir
sucesión temporal) son trabajo de desarrollo G1; la resolución de S4 debe
preregistrarse como regla explícita con su evidencia, no como heurística
oportunista.

### 4.3 Extraction (nuevo holdout)

```text
n ≥ 50–60 documentos INSTRUMENT_DEFINING, estratificado
```

#### Suficiencia de evidencia por familia (AMEND-1)

G1 es un benchmark finito, no una estimación poblacional. Ninguna familia se
declara PASS con muestra testimonial:

```text
positive_gold < 5      → INSUFFICIENT_EVIDENCE   (no se reporta como gate)
5 ≤ positive_gold < 15 → DESCRIPTIVE_ONLY        (métricas calculadas,
                                                  NO se declara PASS)
positive_gold ≥ 15     → GATE_ELIGIBLE           (se aplica threshold)

target ≥ 20 positivos para las familias críticas donde G0 falló:
  coupon_rate_family · day_count · call_put
```

Rationale: con 5/5 aciertos el límite inferior unilateral del 95% de la tasa
real es ~55%; con 20/20 sube a ~86%. Un gate del 95% sobre n=5 solo distingue
"cero errores en cinco" de FAIL — no mide el umbral. La selección de casos
para alcanzar los positivos objetivo se hace por estratificación del universo,
nunca por si el extractor actual sabe resolverlos.

#### Reporte obligatorio por familia

```text
positive_gold
TP · FP · FN
precision · recall · coverage
exact 95% CI (binomial) para precision
gate_eligible: true/false
```

Precision del valor y coverage/recall operacional se reportan por separado:
G0 demostró que precision alta puede coexistir con cobertura insuficiente.

#### Hard gates de precision (umbrales G0, sin reducir)

```text
coupon/rate               ≥ 95%
day_count                 ≥ 95%
maturity                  ≥ 99%
call/put                  ≥ 90%
reset/fixing              ≥ 90%
observation               ≥ 90%
barrier/strike/redemption ≥ 90%

solo aplican si gate_eligible = true
```

### 4.4 Novelty / OSS_DELTA

```text
≥ 80% de casos INSTRUMENT_DEFINING con ≥1 término material
no disponible de forma estructurada en FIRDS/ESAP
```

Denominador exclusivamente `INSTRUMENT_DEFINING`, fijado antes de la selección.
Los lifecycle docs no entran en esta métrica — se evalúan en 4.5.

### 4.5 Lineage (gate nuevo para lifecycle docs)

```text
supplements / corrections / admissions / registration:
  capacidad de relacionar MODIFIES | SUPPLEMENTS | CORRECTS | REPLACES
  contra el documento/instrumento correcto

métricas: precision y cobertura de la relación propuesta
  FP de relación = 0 (hard gate)
  abstención ante evidencia insuficiente = correcta, no fallo
```

## 5. Lo que G1 NO es

- No es un rerun de los holdouts G0 con código nuevo.
- No es una reclasificación retrospectiva del corpus G0 para convertir FAIL
  en PASS — el FAIL queda publicado.
- No incluye optimización de rendimiento Docling (X26 = 1644s/788pp es
  inviable para backfill masivo, pero optimizar antes de validar G1 sería
  prematuro).
- No relaja ningún threshold de seguridad ni de precision.
